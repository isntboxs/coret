## Skill Loading

Before substantial work:

- Skill check: run `bunx @tanstack/intent@latest list`, or use skills already listed in context.
- Skill guidance: if one local skill clearly matches the task, run `bunx @tanstack/intent@latest load <package>#<skill>` and follow the returned `SKILL.md`.
- Monorepos: when working across packages, run the skill check from the workspace root and prefer the local skill for the package being changed.
- Multiple matches: prefer the most specific local skill for the package or concern you are changing; load additional skills only when the task spans multiple packages or concerns.

## Project Context

This repository is Coret, a Linear-like workspace for organizing product work around Workspaces, Teams, Issues, workflows, and Projects.

Scaffold command used:

```bash
bunx @tanstack/cli@latest create my-tanstack-app --agent
```

Follow-up TanStack Intent commands run:

```bash
bunx @tanstack/intent@latest install
bunx @tanstack/intent@latest list
bunx @tanstack/intent@latest load @tanstack/start-client-core#start-core
bunx @tanstack/intent@latest load @tanstack/react-start#react-start
bunx @tanstack/intent@latest load @tanstack/router-core#router-core
```

The CLI scaffold reported that its internal `bunx --bun @tanstack/intent install --map` step did not complete; the explicit Intent install command above succeeded.

## Stack

- React 19 with TanStack Start and TanStack Router.
- Bun is the package manager and script runner.
- Vite is the build tool.
- TypeScript is configured in bundler mode.
- Vitest is available through the generated `test` script.

## Architecture

- `src/routes/__root.tsx` is the document shell and must keep `HeadContent` in `<head>` and `Scripts` in `<body>`.
- `src/routes/**` files are thin TanStack Router shells. They should handle route paths, route auth redirects, loaders, and rendering module route components.
- Route-heavy UI lives in vertical modules, for example `src/modules/workspace/components/home-route.tsx`, `src/modules/welcome/components/welcome-route.tsx`, and `src/modules/team/components/active-team-route.tsx`.
- Domain modules live under `src/modules/<domain>/` with module-local `schemas.ts`, `contract.ts`, `router.ts`, `components/`, and `server/` folders.
- `src/server/orpc/` owns the oRPC runtime seam: base contract, context, client, registry, logging, handler, and shared error utilities. Domain oRPC contracts and routers stay in their module folders.
- `src/db/client.server.ts` owns the Drizzle client. `src/db/schemas/**` remains central because Drizzle and Better Auth need a single schema registry.
- `src/shared/**` contains non-domain shared utilities such as logger, Query Client setup, and `cn`.
- `src/components/ui/**` contains shadcn primitives only. Prefer composing these from module components rather than adding domain behavior to UI primitives.
- `routeTree.gen.ts` is generated by TanStack tooling and is excluded from editor search/watch by `.vscode/settings.json`.
- `vitest.config.ts` is intentionally separate from `vite.config.ts` so tests do not boot the Start/Nitro build plugins.
- All application code is isomorphic by default in TanStack Start. Put server-only behavior behind Start server primitives, `.server.ts` files, or `server-only` markers.
- Do not import `*.server.*` from route/module code that runs on the client. Use a facade with `createServerFn` when route code needs server data.
- Do not import `*.client.*` from route/module code that runs on the server. Use `createClientOnlyFn`, `<ClientOnly>`, or a module facade for browser-only behavior.
- Keep `devtools()` first in the Vite plugin chain and `tanstackStart()` before `viteReact()` unless TanStack Intent guidance says otherwise for a specific upgrade.
- Do not add runtime app code for CodeRabbit.

## CodeRabbit

CodeRabbit is represented as external repository tooling only. There is no runtime SDK, app code, server function, or workflow for it.

- Configure repository access by installing the CodeRabbit GitHub App or enabling this repository in the CodeRabbit dashboard.
- `.coderabbit.yaml` provides repository review defaults for pull requests.
- No CodeRabbit secrets or environment variables belong in the app.

## Environment

Coret currently expects database, auth, OAuth, logging, and public app URL environment variables as defined in `src/env.ts`.

Keep secrets server-side and avoid `VITE_` prefixes unless the value is intentionally public.

## Deployment

The selected deployment adapter is Nitro (agnostic). Build with:

```bash
bun --bun run build
```

Use the generated Nitro output for the target Node-compatible host. Confirm the exact server entry after each Start/Nitro upgrade because output paths can change across versions.

## Known Gotchas

- The first route generation happens during dev/build; do not hand-edit generated route tree output.
- CodeRabbit reviews will not run until the GitHub App/dashboard setup grants repository access.
- Better Auth organizations map to Workspaces and Better Auth teams map to Teams. See `docs/adr/0001-better-auth-with-domain-policies.md`.
- Public Team access is available to Workspace Members. Private Team access requires Team membership in module policy/access functions.
- PWA manifest output is generated as `/manifest.webmanifest`; do not reintroduce `public/manifest.json` unless the PWA setup changes.
